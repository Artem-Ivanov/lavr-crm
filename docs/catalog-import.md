# Импорт номенклатуры: PDF сейчас, адаптер в будущем

Импорт доступен администратору в разделе «Каталог» → «Импорт PDF». Operator и partner не получают доступа к пакетам и управлению каталогом.

## Как загрузить отчёт

1. Выберите текстовый PDF того же вида, что `docs/номенклатура1.pdf`: бренд, артикул, номенклатура, цена и остаток в табличной сетке. Пределы — 5 МиБ, 400 страниц и 50 000 строк. Сканы, защищённые файлы и другие макеты не распознаются автоматически.
2. Укажите фактическую дату и время состояния склада по Москве. Колонка «Остаток» трактуется как общий физический запас. Подтвердите, что цена указана в рублях за назначаемую единицу учёта.
3. Дождитесь сверки. Окно можно закрыть: пакет обрабатывается на сервере, затем доступен в истории. До применения товары не меняются.
4. Проверьте новые/изменённые позиции, физический остаток, текущий резерв и доступное количество. Проверьте единицы `шт`, `кг`, `л`, `м` и назначьте категории. Если единица не указана, сохраняется известная единица существующей карточки; для новой или карточки без единицы применяется `шт`. Фасовка в названии не определяет единицу учёта. Для новых товаров предусмотрена скрытая категория «Неразобранное».
5. Уточните спорные строки либо явно отложите их. Дубли не объединяются, их остатки не суммируются. Наборы и компоненты требуют подтверждения, что это самостоятельный товар с собственным остатком; расчёта состава сборки нет.
6. Примените подтверждённую выборку. Она записывается одной транзакцией. Сохранённый отчёт содержит число созданных/обновлённых/неизменённых/отложенных строк, автора, хеш файла и время наблюдения.

Резервы сайта, идентификаторы товаров, категории и оформление существующих карточек сохраняются. Товар, которого нет в PDF, не обнуляется. Неизвестное значение отличается от нуля. Единицу можно изменить при сверке; очистка выбора возвращает единицу существующего товара либо `шт`. Это правило действует и для ранее подготовленных пакетов при обновлении сверки и применении. Дробный остаток в `шт` блокирует применение строки до выбора фактической единицы учёта. Новые товары без назначенной категории остаются в скрытой категории «Неразобранное».

Если резерв, учётные данные или связи изменились после предварительного просмотра, нажмите «Обновить сверку» и проверьте новые числа. Старое наблюдение не перезаписывает более новое. Повтор применения с прежним ключом возвращает сохранённый результат.

## Количество и цена

Количество поддерживает до трёх знаков после запятой, например 0,955 кг. Штуки остаются целыми. Цена задаётся за одну единицу; сумма каждой строки округляется до копейки HALF_UP, затем суммы складываются. Остаток и резерв хранятся точно в PostgreSQL NUMERIC(13,3). Корзина и сервер не умножают цену на двоичную дробь.

При смене единицы корзина требует повторно выбрать количество. Единицу товара с действующим резервом изменить нельзя. Исторические заказы и ответы идемпотентности не переписываются.

## Два входа, одна сверка

Файловый путь реализован: PDF → нормализованный `CatalogSnapshot` → предварительный просмотр → решения → атомарное применение.

Будущий адаптер реализует порт `CatalogSourceAdapter.fetch_snapshot()` в [catalog_sources.py](../backend/app/catalog_sources.py). Его снимок содержит собственный namespace с префиксом `adapter:`, фактическое время, `stock_scope=main-stock`, `price_type=retail` и строки `CatalogSourceRow`. Каждая строка адаптера обязана содержать постоянный `source_product_id`; артикул не заменяет этот код. `create_adapter_import(db, adapter, author_id=...)` проводит снимок через тот же механизм, что и PDF. В тестах используется локальный адаптер без сетевых вызовов.

Реальный адаптер конкретной учётной системы пока отключён и возвращает `CATALOG_ADAPTER_NOT_CONFIGURED`. Интерфейс показывает это состояние. Нет автоматического переключения владельца данных: один склад обслуживает один namespace, а другой источник не перехватывает товары по артикулу. Переход с PDF на реальный адаптер потребует явного сопоставления постоянных кодов с уже существующими Product.id и решения о владельце учётных полей.

Импорт каталога не подменяет адаптер экспорта заказов. Действующий запрет оформления заказа без настроенной ERP сохраняется; файл сам по себе не включает автономный приём заказов и не выставляет статус «1С подключена».

## Запуск и эксплуатация

В основной Compose-сборке добавлен сервис `catalog-imports` из того же образа backend:

```bash
docker compose --env-file .env.docker up -d --build backend catalog-imports frontend
docker compose --env-file .env.docker logs --tail=100 catalog-imports
```

Для HTTPS-установки сохраните её действующий набор Compose-файлов и используйте тот же список сервисов. Не удаляйте дополнительные overrides, сертификаты или настройки подключения notifier.

Вне Docker обработчик запускается из `backend` после установки зависимостей и миграции БД, с тем же DATABASE_URL и ключами приложения:

```bash
python -m app.catalog_import_worker
```

Одновременно разбирается один PDF. Парсер работает в отдельном процессе без сетевых вызовов, с лимитами 300 секунд, 512 МиБ адресного пространства на Linux и 100 МиБ выходного файла. Контейнер worker ограничен 768 МиБ, одним CPU и 64 процессами. Задания/состояния/исходник хранятся в PostgreSQL, а временные файлы — в закрытом временном каталоге. Исходный PDF не публикуется в медиатеке и не входит в образ.

Сырые PDF очищаются через 7 суток, подробные строки — через 30 суток; отчёт и подтверждённые связи остаются. Очистку выполняет worker. Потерявший lease обработчик не может перезаписать результат нового владельца задания.

Миграции 0007/0008 расширяют точность остатков и добавляют таблицы импорта. Перед обновлением рабочей установки нужен обычный резервный снимок БД. После появления дробных данных откат схемы к целым остаткам автоматически не выполняется.

## API

Все маршруты находятся под `/api/admin/catalog/imports` и требуют admin. Изменения дополнительно требуют Origin и X-CSRF-Token.

| Операция | Маршрут |
| --- | --- |
| Возможности PDF и готовность адаптера | `GET /capabilities` |
| История пакетов | `GET /` |
| Загрузка file/observedAt/priceConfirmed | `POST /` + UUID Idempotency-Key |
| Пакет, summary и страницы rows | `GET /{id}?offset=0&limit=50&filter=all&query=` |
| Построчные/массовые решения | `PATCH /{id}/decisions` + If-Match |
| Повторная сверка | `POST /{id}/refresh` + If-Match |
| Атомарное применение | `POST /{id}/apply` + If-Match и UUID Idempotency-Key |

Точная схема опубликована существующим защищённым `/api/openapi.json`. В административном API импорта количества передаются точными десятичными строками; публичные stock/quantity сохраняют числовой формат в обычных единицах.
