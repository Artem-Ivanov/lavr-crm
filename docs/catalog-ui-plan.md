# Категории, номенклатура и лендинг

**Цель:** менеджер создаёт категорию и добавляет в неё номенклатуру; покупатель находит товар по артикулу, заходит в каталог из категории или панели акций. Основной идентификатор по ответу пользователя — артикул.

**Решение:** вкладка «Каталог» внутри CRM, форма категории, форма товара и таблица номенклатуры. Категория одна на товар. Для уже существующей номенклатуры категория меняется отдельным выбором в таблице. Категории и товары демо сохраняются единым снимком в `localStorage` (`lavr.catalog.v1`). Обработка записи выполняется до изменения UI; при ошибке форма и прежний каталог сохраняются. Заказы продолжают хранить снимок цены и наименования.

**Доменные интерфейсы** (`src/catalog-admin.js`):

- `initialCatalog()` → свежий `{ categories, products }` из демонстрационных fixtures.
- `restoreCatalog(raw)` → проверенный снимок; `null` возвращает начальный каталог, некорректные данные вызывают ошибку.
- `createCategory(catalog, { name })` → новый каталог, автоматически созданный `id`.
- `createProduct(catalog, { name, sku, brand, category, price, stock })` → новый каталог, `id` автоматически, `price` — строка рублей с максимум двумя десятичными знаками, `stock` — целое неотрицательное число/строка.
- `assignProductCategory(catalog, productId, categoryId)` → новый каталог.

Уникальность: названия категорий без учёта регистра/лишних пробелов; комбинация бренда и артикула без учёта регистра/разделителей. У одинаковых артикулов разных брендов могут быть разные товары. Идентификаторы товара/категории не меняются при назначении категории. Цена — положительное безопасное целое число копеек; цена ≤ 1000000000 копеек, остаток ≤ 100000. Название ≤ 160, бренд/артикул ≤ 80, название категории ≤ 80 символов. Новые товары без фото показывают нейтральную иконку.

**Границы:** ручные изменения относятся только к демо. В рабочей системе 1С остаётся источником номенклатуры, артикулов, цен и остатков; категории витрины управляются через CRM. Запись новой номенклатуры определяется серверным адаптером после согласования конфигурации 1С; текущий UI не имитирует такую запись. Панель содержит статичные примеры объявлений и акций с переходом в соответствующую категорию. Редактор акций, загрузка фото, удаление товаров и вложенные категории не входят в этот шаг.

**Порядок выполнения:**
1. Проверки и чистые функции каталога: восстановление, повторные категории/артикулы, точные копейки, недопустимые остатки и связь с категорией.
2. CRM-компонент `CatalogManager.vue`; root подключает реактивный каталог ко всем существующим функциям поиска/корзины/оформления и событиям storage.
3. `LandingPage.vue`: категории, крупный поиск в шапке, панель примеров акций/объявлений. Существующие изображения и иконки, без новых зависимостей.
4. Проверки в Chrome: создание → главная → поиск артикула → корзина → заказ → CRM, обновление страницы/другая вкладка, ошибка сохранения, клавиатура, мобильная ширина. Проверить прошлые сценарии.
