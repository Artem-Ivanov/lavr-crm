# LAVR: витрина автозапчастей и CRM, MVP

## Задача

Покупатель находит запчасть прежде всего по артикулу, а также по названию или бренду, добавляет её в корзину и оформляет заказ без оплаты. Менеджер создаёт категории и добавляет в них номенклатуру, назначает категорию существующему товару, видит заказ в CRM и меняет его статус. Главная страница ведёт в каталог через категории и панель примеров акций/объявлений. Требование пользователя: фронтенд и архитектура будущего обмена с 1С. Конфигурация 1С пока не определена.

## Текущая реализация

Локальный интерактивный прототип: Vue 3 SFC, CSS и Vite. Каталог демонстрационный, редактируется во вкладке CRM «Каталог». Категории и товары сохраняются единым снимком `lavr.catalog.v1` в localStorage, исходные fixtures не меняются. Корзина тоже сохраняется в localStorage; демозаказы и контактные данные — в sessionStorage текущей вкладки. Полное восстановление каталога проверяет данные и связи. Если каталог повреждён или недоступен, показаны исходные демоданные, изменения и оформление приостановлены без перезаписи хранилища. Ошибка записи оставляет форму и прежний каталог; ложное подтверждение заказа не показывается. Оплаты, серверного API, авторизации и реального обмена с 1С нет. Деморежим отмечен в интерфейсе и при оформлении.

В рабочей системе категории витрины принадлежат магазину и управляются через CRM; адаптер может сопоставлять их группам 1С. Источник номенклатуры, артикулов, цены и остатка — 1С. Создание новой учётной номенклатуры из CRM потребует согласованного контракта записи после уточнения конфигурации 1С. OpenAPI проектирует чтение и команды категорий/оформления товара, но не эту запись в 1С.

## Рабочая версия и два режима

Пользователь закрепил модель **тонкого клиента**. Один frontend Vue показывает данные FastAPI; сервер проверяет изменения, хранит деловые данные и определяет права. PostgreSQL содержит категории, проекцию товаров, заказы, настройки сайта/меню, тексты, публикации и связи изображений. Сами файлы хранятся на постоянном серверном media volume. Состояние формы, фильтров, предпросмотра и черновик корзины остаются временным состоянием UI; они не заменяют серверные данные.

- **Пользовательский режим:** главная, опубликованные акции/объявления, категории, поиск по артикулу, карточка товара, корзина и оформление заявки без оплаты. Для MVP вход покупателя не нужен; публичного списка заказов и контактов нет.
- **Административный режим:** вход сотрудника, заказы, категории/оформление товаров, меню и тексты главной, акции/объявления/горячие предложения, медиабиблиотека. Роль `manager` обрабатывает заказы; `admin` управляет всеми этими разделами и обменом. Права проверяются каждым серверным запросом, независимо от frontend-маршрута.

Текущий дизайн лендинга сохраняется. Контент редактируется полями форм внутри готовых шаблонов. Публикации имеют черновик, публикацию и архив, порядок и необязательный срок действия; публичный API фильтрует видимость на сервере. Изменения требуют версии записи и CSRF-защиты; конфликт возвращает `412` без перезаписи чужой работы. Загрузка изображений: JPG/PNG/WebP до 5 MiB, до 4096×4096, alt до 240 символов; проверка декодированием, закрытый предпросмотр и выдача только актуально опубликованных файлов.

Это архитектура следующего этапа, а не уже подключённый backend. Полный контракт и границы данных: [architecture.md](architecture.md), [api.openapi.yaml](api.openapi.yaml). План перехода от демо: [backend-implementation-plan.md](backend-implementation-plan.md).

## Выбранный стек рабочей версии

Пользователь выбрал Python / FastAPI + Vue; команда — один разработчик с опытом Python. Целевой backend: FastAPI, PostgreSQL, SQLAlchemy 2, Alembic. Frontend CRM и витрины: Vue 3 + Vite — выбор подтверждён пользователем. SEO отложено до следующих этапов; необходимость Nuxt оценить после MVP. Обмен с 1С: отдельный Python worker, серверный адаптер и PostgreSQL outbox. Текущий UI уже реализован на Vue; FastAPI и обмен с 1С описаны в архитектуре и ещё не подключены.

## Дизайн

Светлая витрина: графитовый текст, красный акцент, крупная строка поиска по артикулу, бренду или названию, спокойные серые фоны товаров. Верхняя навигация: каталог, CRM, корзина. Автомобильный баннер объясняет подбор по артикулу; категории из текущего каталога ведут к его фильтру. Панель «Акции и объявления» показывает три статичных примера с переходами в каталог, редактора нет. В каталоге карточки товаров, фильтр по категории, бренду, наличию и сортировка по цене. Новые категории и товары без фото используют нейтральные иконки. Адаптивная сетка и мобильная корзина. CRM использует тот же визуальный язык: вкладки «Заказы» и «Каталог», таблицы, поиск, формы категории/номенклатуры и выбор категории для существующего товара.

## Основной сценарий

1. Менеджер открывает `#crm-catalog`, создаёт категорию и товар либо выбирает категорию существующему товару. Категория одна на товар; назначение не меняет его идентификатор.
2. Покупатель начинает с категории/примера акции на главной или поиска по артикулу, бренду и названию; сбрасывает пустой результат.
3. Добавление товара только в пределах демонстрационного остатка; изменение количества и удаление.
4. Оформление: имя, телефон, опциональный email, самовывоз либо доставка с адресом. Итог считает только товары, стоимость доставки согласуется отдельно.
5. Подтверждение явно сообщает, что демозаказ создан в текущей вкладке и не отправлен магазину или в 1С.
6. Заказ появляется во вкладке CRM «Заказы» (`#crm`); разрешены переходы «Новый → Подтверждён → Готов → Завершён», отмена до завершения. Отменённый и завершённый заказ неизменяемы; дальнейшие изменения каталога не меняют снимок цены/состава заказа.

## Границы кода

- `src/catalog.js`: демонстрационные товары и поиск/фильтрация.
- `src/catalog-admin.js`: начальный каталог, проверка полного снимка, создание категории/товара, назначение категории; уникальность названия категории и пары бренд/артикул, цены в целых копейках и целые неотрицательные остатки.
- `src/cart.js`: проверка количества и остатков, итог в целых копейках, восстановление корзины из недоверенного хранилища.
- `src/orders.js`: проверка формы, снимок цены и состава заказа, разрешённые статусы, проверка сохранённых демозаказов.
- `src/App.vue`, `src/main.js`: реактивные экраны, формы и события. Vue выводит пользовательские значения как текст.
- `src/components/CatalogManager.vue`, `src/components/LandingPage.vue`: формы/таблица каталога CRM и главная с категориями и примерами акций/объявлений.
- `src/styles.css`: единые токены и адаптивные стили.
- `vite.config.js`: Vue plugin, локальный dev server и production build. Для размещения используется только `dist/`.
- `docs/architecture.md`, `docs/api.openapi.yaml`: проект серверной части и контракт интеграции; не описывают несуществующий работающий сервер.

## Проверка

Встроенный `node:test`: нормализация артикула, фильтры, восстановление полного каталога, повторные категории/артикулы одного бренда, назначение существующей категории, точные копейки и недопустимые остатки; повреждённая корзина, целое положительное количество, расчёт итогов, контакты/адрес, невозможность пустого заказа и повторного изменения финальных статусов. Production build проверяет Vue templates и связность модулей. Браузерная проверка: создание категории/товара → главная → поиск артикула → корзина → демозаказ → CRM; назначение категории, обновление страницы/другая вкладка, ошибки хранилища, клавиатура и мобильная ширина.
