# Редактор содержимого сайта

Цель — открыть из CRM вкладку «Контент сайта» для администратора и управлять существующим шаблоном лендинга без редактирования исходного кода. Текущий дизайн, адаптивная витрина и тонкий HTTP-клиент сохраняются.

Редактор содержит три раздела: «Главная и меню», «Публикации», «Изображения». Настройки включают реквизиты магазина, заголовки разделов, текст/описание/кнопку/изображение баннера, до 12 пунктов меню с внутренними целями, порядком и видимостью. Публикация — акция, объявление или горячее предложение с текстом, до восьми изображений, целью, порядком, статусом и необязательными сроками показа. Архив заменяет удаление. Библиотека принимает JPG/PNG/WebP до 5 MiB и 4096×4096; файлы выбираются по идентификатору, произвольные URL и HTML-конструктор не используются.

1. `src/content.js` проверяет входные DTO и административные ответы; `src/data/http-api.js` вызывает существующий OpenAPI `/admin/site`, `/admin/publications`, `/admin/media` с CSRF и If-Match. HTTP upload использует FormData. Серверная реализация этих endpoints остаётся частью FastAPI-плана.
2. `src/data/demo-content-api.js` сохраняет один проверенный снимок текстов/ссылок/публикаций в `lavr.site.v1`; чтение перед записью и версии предотвращают незаметную перезапись устаревшего редактора. `src/data/demo-media.js` хранит Blob изображений в IndexedDB только явного демо и создаёт временные object URL для отображения.
3. `ContentManager.vue` и небольшие повторно используемые поля вызывают async provider. Ошибки, 412 и неудачная загрузка не очищают черновик; смена записи, уход и обновление страницы предупреждают о несохранённых данных. Manager не получает редактор и не вызывает административные content endpoints.
4. `App.vue` открывает `#crm-content` только admin, обновляет public site после подтверждённых записей и синхронизирует демоконтент между вкладками. Сохранённое пустое меню действительно пустое.
5. Проверки покрывают публикацию/архив/окно, версии и сохранность при ошибках, реальные Blob/IndexedDB и обновление страницы, CSRF/multipart, запрет менеджеру, XSS как текст, мобильную ширину и касания. Скриншоты подтверждают текущий вид.

Новые зависимости и backend-заглушки не нужны. Для общего рабочего сайта серверные файлы/данные по-прежнему должны сохраняться FastAPI/PostgreSQL/media volume; browser storage не объявляется рабочим сервером.
