# Варианты статистики посещений MIRZAP67

Проверено по официальным источникам 29.10.2026. Это сравнение вариантов: счётчики, аккаунты, зависимости и сервисы не подключались.

## Что такое Umami для этого проекта

Umami — отдельная готовая панель веб-аналитики: посещения и страницы, источники переходов, устройства, цели и события. При самостоятельном размещении приложение Umami и его PostgreSQL обслуживаем мы; его основное хранилище контролируем сами. Это дополнительный сервис, а не модуль CRM. [Описание Umami](https://docs.umami.is/docs), [установка](https://docs.umami.is/docs/install).

У актуальной Umami v3 есть дополнительные функции повторов сессий и тепловых карт. Для предлагаемого первого этапа нужны только нормализованные публичные просмотры и выбранные события, без записи форм/закрытых экранов. Работа без cookies не означает абсолютную анонимность: IP и User-Agent участвуют в расчёте идентификатора с изменяемой солью. [Возможности v3](https://docs.umami.is/docs), [определения метрик](https://docs.umami.is/docs/metric-definitions).

Пользователь выразил условный интерес к варианту Umami и запросил объяснение; установка, включение сбора и новый хостинг этим ответом пока не одобрены. До запуска отдельной задачей согласовать размещение/ресурсы, изолированную БД и срок хранения, доступ к отчётам и разрешённые публичные события. CRM/ЛК и приватные идентификаторы в аналитику не передаются.

Нужны две разные группы показателей. Для бизнеса: просмотры разделов, визиты, оценка уникальных посетителей, источники и достижение целей. Для эксплуатации: память, CPU, длительность запросов, ошибки и доступность. Prometheus предназначен для мониторинга систем и временных рядов; существующий мониторинг сервера сам по себе не даст отчёты о посетителях и воронке. [Prometheus: overview](https://prometheus.io/docs/introduction/overview/).

| Вариант | Что получим | Нагрузка и обслуживание | Данные и ограничения | Когда выбирать |
|---|---|---|---|---|
| Яндекс Метрика | Готовые отчёты по просмотрам, визитам, посетителям, источникам; цели для действий и конверсий | Отдельное приложение и БД на VM не нужны; остаются настройка счётчика и проверка корректности событий | Данные уходят внешнему сервису. Браузерные блокировки и настройки пользователя дают пропуски. Публичная витрина; закрытые экраны CRM исключить | Самый быстрый путь к полезной статистике витрины, если внешний сервис приемлем |
| Umami на своём сервере | Свои отчёты, события, источники и воронки | Дополнительное Node-приложение, PostgreSQL, обновления, резервное копирование и контроль роста БД | Основное хранилище своё; отсутствие cookies не означает отсутствие обработки IP или абсолютную анонимность. Внешние обращения самого сервиса тоже требуют настройки | Когда важнее контроль над данными и команда готова обслуживать сервис |
| Минимальные собственные события в FastAPI/PostgreSQL | Счётчики действий по дням, разделам и ролям; подтверждённые сервером заказы/заявки | Нового сервиса нет, но нужны код приёма, агрегации, отчёта, ограничения входных данных и тесты | Наибольший контроль над составом данных; готовую аналитику придётся писать. Простые агрегаты не дают достоверные уникальные посещения и полноценные сессии | Для внутренней активности CRM или когда достаточно нескольких чисел без внешнего провайдера |

Метрика определяет визит по активности с тайм-аутом, по умолчанию 30 минут; посетители определяются по идентификаторам браузеров в cookies. Поэтому «уникальные» — оценка браузеров по правилам продукта, а не точное число людей. [Метрика: термины](https://yandex.ru/support/metrica/ru/general/glossary).

Для self-hosted здесь предпочтительнее Umami, чем Plausible: Umami требует Node и PostgreSQL, а Plausible CE использует ещё ClickHouse и рекомендует минимум 2 GB RAM для ClickHouse/Plausible. На общей VM с 2 CPU и примерно 2 GiB RAM это существенная дополнительная нагрузка. Увеличение до 3 GB само по себе не доказывает достаточный запас: перед установкой нужны фактические показатели свободной памяти и нагрузки. Официальный фиксированный минимум RAM для Umami в проверенной инструкции не указан. [Umami: установка](https://docs.umami.is/docs/install), [Plausible CE: официальный README](https://github.com/plausible/community-edition), [Plausible CE: БД](https://github.com/plausible/community-edition/wiki/Configuration).

Umami по умолчанию строит идентификатор с использованием IP, User-Agent и сменяемой соли; IP участвует в расчёте, хотя не хранится отдельным полем записи сессии. Данные на self-hosted по умолчанию остаются, пока их не удалить. Предусмотреть срок хранения и обслуживание; при требовании без внешнего обмена проверить `PRIVATE_MODE` и отключение telemetry. Это технические настройки, из них нельзя выводить юридические исключения. [Umami: определения метрик](https://docs.umami.is/docs/metric-definitions), [FAQ](https://docs.umami.is/docs/faq), [настройки окружения](https://docs.umami.is/docs/environment-variables).

## Особенности текущей Vue SPA

1. У сайта hash-маршруты. Для Метрики официальный путь — `defer: true` и ровно один явный `hit` после успешного перехода на разрешённый публичный экран; для действий — `reachGoal`. Передавать нормализованный путь из списка, например `/catalog`, `/product`, `/cart`, а не исходный `location.href`. [Метрика: SPA](https://www.yandex.com/support/metrica/ru/code/counter-spa-setup).
2. Текущий Umami умеет отслеживать hash-маршруты автоматически. Однако явная отправка нормализованных просмотров полезна для запрета закрытых маршрутов и удаления чувствительных параметров; автоматическую отправку при этом выключить, чтобы не удваивать просмотры. Возможны удаление query-параметров и проверка/отмена payload перед отправкой. Точный способ зависит от закреплённой версии. [Umami: SPA](https://docs.umami.is/docs/guides/track-single-page-apps), [настройка трекера](https://docs.umami.is/docs/tracker-configuration).
3. Счётчик не должен получать логины, телефоны, email, адреса, VIN/текст поиска, содержимое форм, токены, номера/ID заказов или URL закрытых экранов. Передавать только заранее разрешённые имена страниц/событий и ограниченные значения. Реферер — максимум домен; UTM — только проверенные значения кампаний. Не включать UserID/identify и передачу данных CRM во внешний счётчик. Метрика отдельно предупреждает о персональных данных в URL, заголовках, UTM и событиях. [Метрика: конфиденциальность данных](https://yandex.ru/support/metrica/ru/general/confidential-data).
4. Вебвизор, карты кликов, автоматическое отслеживание ссылок, автоматические цели/расширенное сопоставление контактов и запись форм в первой версии не нужны. Для Метрики явно проверить их отключение в коде и настройках счётчика; приватные заголовки не отправлять. Не загружать внешний счётчик на закрытых экранах; для переходов между публичной и закрытой частями SPA отдельно проверить его жизненный цикл. [Метрика: параметры инициализации](https://www.yandex.ru/support/metrica/ru/code/counter-initialize).

## Минимальная первая версия

Для витрины: `page_view` с нормализованным разделом, `product_view`, `add_to_cart`, `checkout_start`, `order_created` после подтверждения успешного создания сервером. Не считать клик «Оформить» завершённым заказом. При необходимости `contact_click` как отдельная цель; клик не равен звонку или заявке. Проверить исходную загрузку, переходы назад/вперёд, повторный рендер и отсутствие дублей. Не собирать пользовательский текст или персональные данные.

Для CRM достаточно своих дневных агрегатов успешных бизнес-действий с ролью `admin`/`operator`/`partner` и доступом к общему отчёту только у администратора. Индивидуальную историю действий сотрудников и audit log не подменять аналитикой посещений. Без временных идентификаторов первая версия честно показывает количество событий; сессии и уникальных посетителей следует отложить или отдельно определить правила идентификации, дедупликации и хранения. Внешний счётчик для этого не нужен.

Логи nginx/Caddy годятся как ограниченный запасной вариант для числа HTTP-запросов, статусов и грубых источников. В стандартных access-логах могут быть IP, URL, referer и User-Agent. Hash-фрагмент не передаётся при HTTP-запросе, а переход внутри SPA не требует новой загрузки документа: логи не восстановят просмотры разделов, корзину или реальных уникальных людей. [nginx: access log](https://nginx.org/en/docs/http/ngx_http_log_module.html), [RFC 3986, раздел 3.5](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.5).

Рекомендация: для публичной витрины начать с Метрики с небольшим явным набором событий, если внешний сбор данных принят владельцем. Для внутренней активности CRM — собственные агрегаты успешных действий. Umami рассматривать, если нужен именно свой полноценный аналитический сервис; сейчас его не устанавливать.

Не проверялись реальные значения трафика, запас RAM и готовность правовых документов сайта. Любая браузерная статистика имеет пропуски; число подтверждённых заказов сверять с БД приложения.
