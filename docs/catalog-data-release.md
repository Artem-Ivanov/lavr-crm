# Начальный каталог из PDF

Пакет `catalog/releases/pdf-16378dad/manifest.json` связывает все 24 689 строк
исходного `docs/номенклатура1.pdf` с утверждёнными категориями, единицами и общими
изображениями. Это однократная инициализация пустого каталога. Последующие файлы
загружаются штатной кнопкой импорта; существующие привязки источника сохраняются.

## Схема и код

Физический остаток `шт` сохраняет тысячные доли; заказ и резерв `шт` остаются
целыми. Миграция `0009_fractional_piece_stock.py` меняет только CHECK constraint,
без округления и изменения данных. Её SHA-256 закреплён в `ops/deploy_catalog.py`:
`eef6c284f54a2bd69034ccbb8717fadd49554419c5ea34fca985f14f54700472`.

Перед первым применением оператор проверяет опубликованный полный SHA в
`origin/master`, исходники, миграцию и результаты локальной репетиции. На VPS из
этого Git-коммита устанавливаются два файла в приватный control-каталог:
`ops/deploy.py` как `deploy-base-0009.py` и `ops/deploy_catalog.py` как
`deploy_catalog.py` (mode 0700). Рабочий старый `deploy.py` пока сохраняется.

```sh
python3 /home/deploy/lavr-crm-deploy/deploy_catalog.py FULL40SHA
```

Оператор сохраняет все обычные проверки Git, конфигурации, контейнеров, backup,
maintenance и health. Разрешает только добавление конкретной миграции 0009 с
указанным хешем. Содержимое таблиц сравнивается до/после, кроме номера Alembic;
media сравниваются полностью. Только после успеха под общим deploy lock рабочий
контроллер атомарно заменяется версией для 0009; старый сохраняется отдельно.
Повтор того же успешно проверенного SHA завершает установку контроллера, если
предыдущий процесс прервался между успешной выкладкой и заменой файла.

При ошибке до импорта данных candidate image выполняет `alembic downgrade 0008`
до запуска старых образов. Если downgrade или проверка сохранности не проходит,
старые образы не запускаются, maintenance остаётся включённым. Dump автоматически
не восстанавливается. После загрузки дробных остатков в штуках downgrade
запрещён: откат допускается к совместимому с 0009 образу или через исправление
вперёд. Старый образ с неизвестной ему revision 0009 запустить нельзя.

## Данные и изображения

После успешной выкладки 0009 делается отдельная приватная резервная копия БД и
media. Каталог должен быть пуст и в административном API. Не удаляйте реальные
карточки, чтобы пройти эту проверку.

CLI использует существующие apply/import/media функции приложения:

```sh
python -m app.catalog_release \
  --manifest /catalog-release/manifest.json \
  --pdf /catalog-source/номенклатура1.pdf \
  --assets /app/seed-media/catalog-types \
  --receipt /catalog-journal/receipt.json
```

Запускается одноразовый контейнер того же backend image с прежними backend env,
network и media volume, без dependencies и без entrypoint миграций/bootstrap.
`/catalog-release` и PDF монтируются read-only из проверенного VPS Git checkout;
`/catalog-journal` — отдельный приватный каталог, доступный UID 1000. Приложение,
изображения и PDF по SSH не загружаются. `--author-id` нужен, только если активный
администратор не единственный.

До записи проверяются хеши PDF/manifest/изображений, полное покрытие строк,
категории, подписи исходных строк и формат изображений. Существующие шесть
категорий сохраняют ID, флаги и порядок. Новые сначала скрыты, товары появляются
со штатной скрытой presentation. Все утверждённые категории и карточки с
изображениями публикуются одной транзакцией после применения склада.
В той же транзакции итоговые категории фиксируются в строках сохранённого отчёта.

Приватный receipt сохраняет время первой загрузки, import ID, исходный ETag,
idempotency key, привязки строк/медиа/категорий и этап выполнения. Повторять нужно
тот же manifest и тот же receipt; дата при повторе не меняется. При потере receipt
CLI восстанавливает пакет по детерминированному upload key, если сохранены строки
импорта. После их истечения восстановление без привязок отклоняется; повторно
создавать товары вслепую нельзя. Одновременно работает только один release CLI.

После применения проверяются число карточек, точные цены/остатки/единицы,
категории, медиа, различие двух одинаково названных позиций с разными ценами и
повтор без новых записей. Публично проверяются поиск, фильтры и загрузка картинок,
в административном интерфейсе — единицы, импорт и состояние товаров.
